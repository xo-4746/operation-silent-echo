Case 1 — The sloppy developer

unsolvedEcho's first marker

The finance team's intranet portal was built in a hurry by a junior developer, who was told to "remove all debug stuff" before go-live. They missed one thing — and Echo knows how to read source code. Find Echo's first marker.

"Debug stuff" in web pages often hides in HTML comments. View the page source (Ctrl+U) and look for something that doesn't belong. What format do developers use to encode binary-ish data in text?
📌 Debrief: Debug leftovers in production HTML — comments, disabled fields, hidden inputs — are a real and common leak. Part of every security review: check what shipped, not what was intended. (Relevant to secure code review and incident-response practice.)

Case 3 — The session jar

unsolvedadmin portal artefacts

Echo used the compromised svc_backup account to touch the finance admin portal. The portal stores its state in your browser — but it's disguised. Log in below and inspect what it leaves behind.

F12 → Application tab → Local Storage (or Storage). One key looks odd. The value is encoded with the most famous letter-shift cipher — 13 positions. (Also check the Console tab — the portal chatty-logs its session.)
📌 Debrief: Browser storage (localStorage, cookies, sessionStorage) routinely holds session tokens and user data. Credentials and sessions harvested from a compromised finance workstation are how attackers move from "one weird DNS alert" to full application access — this is exactly the "suspicious browser activity" the SOC flagged in the brief.

Case 4 — The contractor badge

unsolvedfrom the HR contractor-badge system

The HR system renders this "digital contractor badge" for the intranet using a small embedded vector image. Echo claims the fourth marker is drawn right on it — but nobody sees it. Inspect the badge itself.

SVG images are text. Right-click the badge → Inspect. Three "parts" hide at different visibility levels: one in a nearly-invisible colour, one in a <desc>, one in <metadata>. Join part1 + part2 + part3 in order.
📌 Debrief: Images and documents leak metadata — SVG text layers, EXIF, document author fields. "Invisible" is not "removed". Never accept a file at face value during an investigation.

The compromised account in Case 2's log is svc_backup — count its letters (9). Undo a Caesar shift of 9... and if the result looks wrong, try it in the other direction (shift −9, i.e. +17). Letters only; the symbols stay put.
📌 Debrief: Classic ciphers still appear in malware notes, scratchpads and C2 strings. Knowing which shift/cipher was used comes from context clues — the attacker's habits across the whole incident. Forensics is pattern-work across artifacts.

🎉 Breach confirmed — all flags recovered!

Echo's six markers are decoded. Your incident timeline: the svc_backup service account was misused to run CSV exports of financial records at 03:41, the finance admin portal's browser session was tampered with on a compromised workstation, and the data left the network via DNS tunnelling to a fake "metrics CDN" — the traffic that finally triggered the 08:42 alert.

Recommended actions: isolate finance.wkstn-04, rotate the svc_backup credentials, block and sinkhole the fake CDN domain, review what the service account exported, and add export-anomaly and DNS-entropy rules to SIEM monitoring.
